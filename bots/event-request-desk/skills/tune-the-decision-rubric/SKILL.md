# Tune the decision rubric

Part of the Event Request Desk agent preset.

Inputs: what the user cares about this quarter, plus the last few event calls they made by hand.

Steps:
1. Start from the five defaults: audience, fit, cost, timing, relationship. Ask which matter most right now and what is missing, one question at a time.
2. Take criteria of their own. Common ones for events: whether an exec is already going, whether the date sits near a launch, whether a competitor is sponsoring, whether the organizer delivered the audience they promised last time, whether the team gets a stage or only a logo.
3. Weight it. Equal weights are the default and are fine. When they want one criterion to dominate, double it and say what the new total is.
4. Set thresholds in their words: what is an automatic yes, what is an automatic no, and what always comes to a human no matter the score.
5. Add hard rules that skip the score entirely. Anything above the spend cap, a date inside a blackout week or the week of a launch, a logo-only package they never take, travel beyond a distance they set. Each rule gets a one line reason.
6. Backtest before you save. Re-score the last five decided requests with the new rubric and show every place it disagrees with what they actually did. Ask about each disagreement rather than assuming the rubric is right.
7. Save the rubric to memory, one fact per criterion and one per hard rule. Then re-score everything open in the queue and report which recommendations moved.

Output: the rubric written out plainly, the backtest table, and the list of queued requests whose recommendation changed.

Never change a rubric quietly. Every edit gets shown and confirmed first.

Save the rubric in the event desk folder.
